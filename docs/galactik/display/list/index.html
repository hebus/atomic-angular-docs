List

An accessible list of selectable rows built on @angular/aria/listbox, with composable slots for content lists, action menus and navigation lists.

List is a container of selectable rows built on @angular/aria/listbox (role="listbox"/role="option"). ListItem is a row, and a set of slot components/directives (ListItemText, ListItemLeft, ListItemIcon, ListItemAvatar, ListItemAction, ListItemChevron, ListItemExpander) compose the row content for content lists, action menus, navigation lists and tree-style rows. A row can also carry one action (typically a delete) that a keyboard user reaches with a key rather than with Tab — see Row action and its key.

Minimal example

A single-selection list

How it works

List composes @angular/aria/listbox's Listbox as a host directive on its own host element (not a wrapper), and ListItem composes Option the same way — required so a projected ListItem resolves its ancestor Listbox through the element-injector hierarchy, which an ng-content wrapper would break. Every selection, keyboard-navigation and ARIA-reflection concern (aria-selected, aria-disabled, roving tabindex, typeahead) comes from @angular/aria, not from galactik.

By default, selectionMode="follow" means moving keyboard focus (arrow keys) immediately changes the selection — the listbox default. Set selectionMode="explicit" (paired with multi, typically) whenever a row also carries its own interactive affordance like ListItemAction, since "select on focus" would otherwise fight with reaching that action.

Row action and its key

A ListItemAction is not focusable: its host ListItem is a listbox option, and ARIA forbids an option from containing an interactive control. A mouse user clicks the icon, which appears on hover. A keyboard user presses the action's key while the row has focus, and ListItem calls the action's trigger() — your (click) handler fires exactly as it would for a click.

That key is declared on the action (keys, Delete by default) and made discoverable in three ways, because no single one reaches everybody:

  • aria-keyshortcuts on the row, set from keys;
  • a sentence (description), rendered visually hidden and linked to the row by aria-describedby, so a screen reader reads it when the row takes focus. aria-keyshortcuts alone is not reliably read: it depends on the reader and its settings, and is then the raw key name, in English;
  • a second line in the row (only when description is set), shown only while the row has keyboard focus (:focus-visible): the same sentence with the key set apart as a keycap. It is hidden otherwise — the mouse has the click, and showing it on hover would move the rows under the pointer. The row grows by that one line, and its trailing tag and action stay vertically centred on it. The rows below move down by that height while the row is focused, and back up when the focus leaves: reserving the space, overlaying the line and animating the height were tried and look worse, so the shift is accepted.

Both visible and hidden copies are aria-hidden or kept out of the option's name, so nothing is announced twice. A disabled action promises nothing: no key, no sentence, no line.

Name the key of a row action

Galactik has no translation layer: the sentence and the key's name are yours to provide. description must contain shortcut as is for the key to be set apart as a keycap inside it. A key that only exists on some keyboards is the caller's to add — a MacBook has no dedicated Delete (it is fn+⌫, and ⌫ alone emits Backspace), so declare both there. isApplePlatform() is exported for that.

A delete action with a translated, announced key

The action does not have to be a delete: keys takes any KeyboardEvent.key values (["Enter"], ["F2"]…), and the first one names the action in aria-keyshortcuts. There is still one action per row: ListItem triggers the first ListItemAction it projects.

Another icon, another key

The icon is projected content and the key is keys, so an action is not a delete unless you make it one. Here a rename: a pencil, answering to F2 (the key file managers use). What the action does is whatever your (click) handler does — the key only calls it.

A rename action on F2, with its own icon and sentence

The hover colour is part of the row, not of the action: every ListItemAction turns to the error colour on keyboard focus and when hovered, since the delete is its main use. There is no class input to change that, and an icon is the only thing you control. If an action needs its own look, or several actions side by side, it is not a ListItemAction — see Limits.

Show a hint while the keyboard is in the list

A list is a single tab stop and the arrow keys do the rest, which nothing tells a keyboard user. List.keyboardFocused is true while the keyboard focus — :focus-visible, so not a mouse click — is inside the list, which is exactly when a hint is useful. Read it through the list template reference.

A navigation hint shown only to the keyboard

Tree rows

depth indents a row by 20px per level, and ListItemExpander renders the rotating expand/collapse chevron. In today's listbox-backed List, tree behavior is style only — expansion state and which children render is entirely up to the consumer; there is no role="tree" keyboard semantics yet (a future @angular/aria/tree-backed variant will add it).

Limits

One action per row. ListItem looks for a single ListItemAction (the first it projects) and gives it the key. That is a property of the component, not an omission of this page.

Projecting a second one does not fail, but only half works:

  • the second icon is drawn and reacts to the mouse — its (click) fires;
  • it is unreachable from the keyboard: the row sets aria-keyshortcuts and aria-describedby from the first action only, and a key press only ever triggers the first;
  • each action still draws its own hint line on keyboard focus, so a focused row would advertise a key that does nothing.

Do not use it that way. When a row needs several actions, or an action with its own look, use a component that can hold several focusable controls: RowGrid is a keyboard-navigable ARIA grid whose rows hold any number of them — Tab enters the focused row and walks its controls, Enter activates the row.

No editable content in a row. A ListItem is a listbox option: ARIA forbids an interactive element inside it, and the row takes Delete (and Backspace on a Mac) for its action whatever has the focus. A row that holds a text field, a select or any other control is not a list row — use RowGrid instead.

The limit is on actions, not on keys: keys may list several KeyboardEvent.key values (["Delete", "Backspace"]), all of which trigger the same action.
